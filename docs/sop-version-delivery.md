# 文档版本提交与历史读取：开发候选

本批承接 `docs/sop-version-capture.md`（快照捕获说明）。功能默认关闭，不能直接替换正式服务。

## 已实现的连接
- 工作空间映射为私有组织，团队空间映射为私有仓库；名称使用固定编号，页面不按标题或用户建仓库。
- 原生新建、正文保存、标题/图标、同空间排序、复制、软删除与回收站恢复接入同事务快照。
- 修改人来自文档认证身份；固定工作空间/用户编号映射到提交作者地址。多人保存记录完整共同作者，不复制用户密码。
- 此处是作者身份映射，不是为每位同事建立后台登录账户，也没有实现双系统单点登录。
- 持久任务按空间串行发送；同空间分配屏障、租约与固定快照避免乱序、重复任务和读取最新正文冒充旧版本。
- 私有组织、仓库编号、安装标识与描述共同校验；曾经绑定的仓库丢失或转公开时阻断，不自动接管或重建。

## 原子提交协议
多文件修改接口没有预期分支头参数，不能仅凭调用成功声称防并发覆盖。
本实现先从已知提交建立任务暂存分支，写入不可变任务文件与当前页面文件，校验父提交、变更路径及精确内容。
随后以 `old_commit_id`（预期旧提交）、`new_commit_id`（新提交）和 `force=false`（禁止强推）原子更新目标分支。
响应丢失时先识别既有任务；远端另有修改则阻断，不重写对方内容。
本次核验了固定版本后台的真实接口说明；带认证的真实后台写入尚未完成联调，现有发送专项使用接口模拟。
任务暂存分支当前保留；长期分支回收和容量测试尚未完成，不作为规模化上线候选。

## 文档页面
顶部新增版本记录入口，显示最近已捕获版本的状态，不把尚在输入的内容误报为已入库。
可分页查看版本及作者、只读打开指定提交的正文。接口前后检查当前权限与所在空间，禁止使用最新内容替代丢失旧版。
历史正文保留文字和表格，复杂静态布局简化；媒体、外部引用和最新评论不随意加载，显示明确范围提示。
完整媒体历史、可视化差异、恢复任意旧提交及旧协作窗口防覆盖尚未实现。回收站恢复不等同于历史版本恢复。

## 配置
从 `.env.example`（环境配置示例）复制可选项到专用环境，不把真实值提交到仓库。
- `SOP_VERSION_CAPTURE_ENABLED`（版本捕获开关）：默认关闭。
- `SOP_VERSION_DEBOUNCE_MS`（停笔等待毫秒）与 `SOP_VERSION_MAX_DEBOUNCE_MS`（连续输入上限毫秒）：开启时默认五秒和三十秒。
- `SOP_GITEA_SYNC_ENABLED`（发送开关）：默认关闭，开启必须同时开启捕获。
- `SOP_GITEA_URL`（固定后台来源地址）：不接受内嵌密码、查询参数或路径，禁止携带凭据跟随重定向。
- `SOP_GITEA_TOKEN`（后台服务令牌）：仅服务端使用，不进入页面、日志、快照或仓库。
- `SOP_GITEA_INSTANCE_ID`（安装实例固定编号）：首次配置后保持不变，用于核对已有组织与仓库归属。
- `SOP_GITEA_ALLOW_HTTP`（私有明文网络显式开关）：默认关闭；正式环境使用加密连接。
后台连接账号应仅具备创建项目私有组织和仓库所需权限，不使用站点管理员令牌处理普通文档。
